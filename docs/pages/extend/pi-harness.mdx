# Using the Pi Harness

Centaur can run [Pi](https://github.com/earendil-works/pi) as a session
harness alongside Codex, Claude Code, Amp, Nanocodex, and Hermes. Start a
Slack, GitHub, or Linear thread with `--pi`, or set `pi` as a channel or
deployment default.

The sandbox keeps one `pi --mode rpc` process per thread. Pi saves the session
on disk and the harness starts Pi with `--continue`, so an interrupt, a model
switch, or a sandbox restart with persistent state resumes the same
conversation.

## Credentials

Pi supports API-key auth only. It reads `ANTHROPIC_API_KEY` and
`OPENAI_API_KEY` from the sandbox environment, where they hold iron-proxy
placeholders that the proxy replaces with the real keys. Anthropic follows
`CLAUDE_CODE_AUTH_MODE` and OpenAI follows `CODEX_AUTH_MODE`; each must be
`api_key` for Pi to use that provider. api-rs refuses to start with `pi` as the
default harness when `CLAUDE_CODE_AUTH_MODE` is `access_token`.

## Configuration

| Variable | Purpose |
|---|---|
| `PI_MODEL` | Default model as `provider/id`, for example `anthropic/claude-opus-4-8` or `openai/gpt-5.5`. When unset, Pi picks a default from the providers it has keys for. |
| `PI_THINKING` | Default thinking level: `off`, `minimal`, `low`, `medium` (default), `high`, `xhigh`, or `max`. Pi clamps it to the model. |

Set both through `sandbox.extraEnv`. A per-thread `--model provider/id`
overrides `PI_MODEL`, and `-rsn <level>` sets the thinking level for one turn
(`none` turns thinking off).
