# Quickstart

This guide gets you from a fresh checkout to a working local Centaur stack. You
do not need a full production Kubernetes installation for local setup: a
lightweight k3s-based cluster is enough. The happy path is: point `kubectl` at
that cluster, bootstrap the required infra Secret, run `just up`, verify the
API, then run one agent turn without Slack. If you want the easiest small-host
path first, start with [Running Centaur on a Mac Mini-style
setup](/mac-mini-setup).

If you want an agent to drive setup with you, point it at these docs: every page
is available through `/llms.txt`, `/llms-full.txt`, and static Markdown files
such as `/md/quickstart.md`.

## 1. Install prerequisites

From the repo root:

```bash
brew install just kubectl helm jq
```

You also need Docker and a local Kubernetes cluster. This can be lightweight:
k3s works on a small VPS, DigitalOcean droplet, Linux box, or Mac Mini-style
host. Docker Desktop with Kubernetes enabled, kind, and minikube are also fine
as long as `kubectl` points at that local cluster and it can run the Helm chart.
The [Mac Mini-style setup guide](/mac-mini-setup) walks through the k3s path
and includes notes for macOS/kind local evaluation.

Check the target before booting Centaur:

```bash
kubectl config current-context
kubectl get nodes
```

The `Justfile` builds local images named `centaur-api-rs:latest`,
`centaur-iron-proxy:latest`, `centaur-slackbotv2:latest`,
`centaur-feishubot:latest`, and
`centaur-agent:latest`, then deploys `contrib/chart` with
`contrib/chart/values.dev.yaml`.

## 2. Export bootstrap secrets

The default local chart expects one infra Secret named `centaur-infra-env`.
`just bootstrap-secrets` creates it from your shell environment.

`just bootstrap-secrets` currently requires these shell variables:

```bash
export OP_SERVICE_ACCOUNT_TOKEN=...
export OP_VAULT=...
export SLACK_BOT_TOKEN=...
export SLACK_SIGNING_SECRET=...
export SLACKBOT_API_KEY=...
```

Create the Slackbot app at [api.slack.com/apps](https://api.slack.com/apps).
Use the app's Bot User OAuth Token for `SLACK_BOT_TOKEN` and its Signing Secret
for `SLACK_SIGNING_SECRET`.

`OP_SERVICE_ACCOUNT_TOKEN` and `OP_VAULT` let [iron-proxy](https://docs.iron.sh)
resolve model and tool credentials through 1Password. `SLACK_SIGNING_SECRET`
and `SLACKBOT_API_KEY` are API boot requirements in the current chart.
`SLACK_BOT_TOKEN` is required by the default local bootstrap because Slackbot is
enabled in `values.dev.yaml`; use a real token if you want to test Slack.

`SLACKBOT_API_KEY` is a static service token. The API bootstraps that value into
Postgres on startup, so it must exist before `just up`.

Application-level model and tool secrets, such as `OPENAI_API_KEY`,
`ANTHROPIC_API_KEY`, `AMP_API_KEY`, and `GITHUB_TOKEN`, should live in
1Password or the configured [iron-proxy](https://docs.iron.sh) secret source. Sandboxes receive
placeholder values and [iron-proxy](https://docs.iron.sh) injects the real credentials only on approved
outbound requests.

The default harness is `codex`, so `OPENAI_API_KEY` must exist in the configured
secret source before Slack agent turns can complete. Use explicit harness
selectors only when you want a non-default harness such as Amp or Claude Code.

## 3. Boot the stack

```bash
just up
```

That runs:

1. `just bootstrap-secrets`
2. `just build`
3. `just deploy`

Check the namespace:

```bash
just status
```

The local bootstrap also creates the Console admin, API key, and encryption
secrets. Before inviting more users or granting tools, review default roles and
sandbox capabilities in
[Advanced Permissioning](/secrets/advanced-permissioning#configure-the-console).

## 4. Verify the API

The API exposes localhost inside its own deployment. Localhost bypasses external
API-key auth, which is why the health check runs through `kubectl exec`:

```bash
kubectl exec -n centaur deploy/centaur-centaur-api-rs -- \
  curl -fsS http://localhost:8080/healthz
```

Expected shape:

```json
{"ok":true}
```

## 5. Run an agent turn

Before testing Slack, run the local smoke test. It uses the same durable agent
API that Slackbot uses: spawn or reuse a runtime, persist a message, enqueue an
execution, and poll the execution state until the result contains `PONG`.

```bash
just smoke
```

The successful result includes the terminal execution row. The important fields
are:

```json
{
  "status": "completed",
  "result_text": "...PONG..."
}
```

If the smoke test times out or fails, start with the local stack state:

```bash
just status
just logs api
kubectl get pods -n centaur -l centaur.ai/managed=true
```

If you changed the namespace or release name, set `CENTAUR_NAMESPACE` and
`CENTAUR_RELEASE` before running `just smoke` so the recipe targets the right
deployment.

## 6. Optional: connect GitLab projects

Create a dedicated GitLab Personal, Project, or Group Access Token that GitLab
accepts in the `PRIVATE-TOKEN` header for `GET /api/v4/projects`. The Token must
also be able to clone every project Centaur should offer. A deploy token or
username/password that works only for Git clone is not sufficient for automatic
project listing. Enabling merge-request publication additionally requires the
minimum rights to push branches and create merge requests. Store the Token in a
Kubernetes Secret under a key such as `token`; do not put it in a values file,
clone URL, command argument, or sandbox variable.

Validate the credential against the projects API before enabling the feature.
A JSON array is expected. A redirect to `/users/sign_in` means GitLab did not
accept the credential as an API Access Token.

Configure the catalog and workspace in a private values file:

```yaml
workspaceRepositories:
  enabled: true
  gitlab:
    baseUrl: https://git.example.test
    egressCidrs: [192.0.2.44/32]
    secretRef: centaur-gitlab
    secretKey: token
  storage:
    className: example-rwx-storage
    size: 20Gi
    accessMode: ReadWriteMany

gitlabPublishing:
  enabled: true
  secretRef: centaur-gitlab
  secretKey: token
```

`baseUrl` remains the real hostname used for TLS and virtual-host routing;
`egressCidrs` is the corresponding fixed network destination for NetworkPolicy.
On a guaranteed single-node cluster, `ReadWriteOnce` is sufficient. Use
`ReadWriteMany` when the sandbox and lifecycle jobs can run on different nodes.

For an HTTP-only private GitLab, the risk acceptance must be explicit:

```yaml
workspaceRepositories:
  gitlab:
    baseUrl: http://git.example.test:82
    allowInsecureHttp: true
    egressCidrs: [192.0.2.44/32]
```

Plain HTTP exposes the shared read/write Token and repository contents to
network observers. Prefer HTTPS.

After deployment, open **New chat** in Console, enter the task, select several
projects or **No project**, and start the task. The Session keeps that repository
set for follow-up messages. Use **Add projects** to extend it. After execution,
review the immutable ChangeSet and test evidence, then choose **Create MR**. Only
the task initiator or a Centaur administrator can approve. A partial failure
keeps successful merge requests and retries only failed repositories.

## 7. Optional: setup China Feishu

Use the China platform at `open.feishu.cn/app`:

1. Create an enterprise self-built application and enable bot capability.
2. Grant the message receive/send and user identity permissions required by the
   application. Console OAuth requires access to the enterprise email returned
   by user info.
3. Under **Events and Callbacks**, select long connection and subscribe to the
   receive-message event whose event key is `im.message.receive_v1`.
4. Enable interactive card callbacks, set the application's availability range,
   create a version, and have an enterprise administrator publish it.
5. Store the app ID, app secret, bot open ID, and a dedicated internal api-rs key
   in a Kubernetes Secret. Do not reuse the GitLab Token.

Enable the ingress with an explicit tenant allowlist:

```yaml
feishubot:
  enabled: true
  secretRef: centaur-feishu
  appIdKey: app-id
  appSecretKey: app-secret
  botOpenIdKey: bot-open-id
  apiKeyKey: api-key
  allowedTenantKeys: [tenant-example]
```

The chart pins one replica and a `Recreate` rollout because the application has
one active long connection. A direct message starts a task and then shows the
project picker. Follow-ups reuse that Session. Send `/projects` to add projects
or `/new` to close the active task before starting another. In a group, mention
the real bot; Centaur binds the Session to that root topic.

To enable Console login with China Feishu, create a separate login app or client
and register this exact callback:

```text
https://console.example.test/auth/feishu/callback
```

Then configure:

```yaml
console:
  publicUrl: https://console.example.test
  feishuLogin:
    enabled: true
    secretRef: centaur-feishu-login
    clientIdKey: app-id
    clientSecretKey: app-secret
    allowedTenantKeys: [tenant-example]
```

Console links users by `(tenant_key, union_id)`, requires enterprise email, and
does not grant administrator access unless the existing bootstrap-admin policy
does so. Bot messaging continues to work without Console login; login is needed
for the browser review surface.

Verify the deployment before sending a real message:

```bash
kubectl get deploy,pod -n centaur -l app.kubernetes.io/component=feishubot
kubectl exec -n centaur deploy/centaur-centaur-feishubot -- \
  curl -fsS http://localhost:3005/health
kubectl exec -n centaur deploy/centaur-centaur-feishubot -- \
  curl -fsS http://localhost:3005/ready
```

If `/health` succeeds but `/ready` returns 503, inspect Feishubot logs and the
China Feishu app credentials, version, tenant availability, and long-connection
configuration.

Rollback the write path first: set `gitlabPublishing.enabled=false` to stop new
publication approvals while preserving review. Then disable `feishubot.enabled`
or `console.feishuLogin.enabled` independently. Disable
`workspaceRepositories.enabled` only after active development Sessions no longer
need Workspace preparation or recovery.

## 8. Setup Slack integration

Slack needs to reach the Slackbot webhook at a public HTTPS URL. Configure your
network, ingress, or local tunnel so the Slackbot route is reachable at:

```text
https://<your-host>/api/webhooks/slack
```

In your Slack app's **Event Subscriptions** settings, set the Request URL to the
Slackbot webhook URL above.

To use Block Kit buttons or selects, enable **Interactivity & Shortcuts** and
set its Request URL to the same Slackbot webhook URL. Each interaction is
delivered to workflows as `slack.block_action.<action_id>` with the selected
value and sanitized Slack user, team, channel, thread, and message metadata.

Subscribe to the `app_mention` bot event. For a minimal channel-mention test,
the app also needs Bot Token Scopes that let it read mentions and write replies,
for example `app_mentions:read` and `chat:write`. If you enable DM events such
as `message.im`, Slack will also require direct-message scopes such as
`im:history`.

Save changes and reinstall the app.

## 9. Try Slack mentions

Invite the bot to a test channel and mention it:

```text
/invite @<your bot's username>
@<your bot's username> reply with exactly PONG
```

Slack messages without a harness flag use Codex. Add a selector such as
`--amp`, `--claude`, or `--pi` only when you want to override the default.

If Slack receives the mention but no agent runs, inspect Slackbot logs:

```bash
just logs slackbot
```

You should see `POST /api/webhooks/slack`.
