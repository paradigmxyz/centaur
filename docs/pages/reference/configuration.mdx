# Configuration

Most Centaur settings come from Helm values and are rendered into service
environment variables by service-specific templates under `contrib/chart/templates/`.

Use these as the main extension points:

| Source | Use |
| --- | --- |
| `secretManager.existingSecretName` | Required runtime secrets such as database, Slack, sandbox signing, and 1Password credentials. |
| `api.extraEnv` | API feature flags, worker tuning, retention, observability, and deployment-specific overrides. |
| `apiRs.extraEnv` | Rust API feature flags, telemetry exporter settings, and deployment-specific overrides. |
| `apiRs.metrics.*` | Prometheus/VictoriaMetrics scrape metadata for the Rust API `/metrics` endpoint. |
| `slackbot.extraEnv` | Slackbot HTTP, Slack, feedback, and cross-org behavior. |
| `sandbox.extraEnv` | Extra variables copied into every sandbox pod through `KUBERNETES_SANDBOX_EXTRA_ENV`. |
| `overlays.sources` | Ordered repo-cache-backed overlay repos for tools, workflows, and skills. Each source accepts an optional HTTP(S) `cloneUrl`; subdirs default to `tools`, `workflows`, and `.agents/skills`. |
| `repoCache.gitCredentials` | Secret-backed username and token used to clone private Git remotes. |
| `workspaceRepositories.*` | Durable task repository catalog, Workspace PVC, and Provisioner settings. |
| `gitlabPublishing.*` | Human-approved GitLab branch and merge-request publication. |
| `feishubot.*` | China Feishu self-built app ingress, tenant policy, probes, and metrics. |
| `console.feishuLogin.*` | China Feishu OAuth login and tenant admission policy for Console. |
| `overlay.systemPrompt` | Small inline prompt overlay escape hatch. |

Application tool credentials are not listed here. Tool plugins declare those
secrets in `tools/**/pyproject.toml`; Centaur resolves them through `secret(...)`
and iron-proxy instead of treating them as global platform configuration. Git
credentials used to fetch the plugin repositories are separate and configured
with `repoCache.gitCredentials` or `toolServer.gitCredentials`.

as Helm values. Configure them in **System Settings** before new principals are
created. Changing a default does not rewrite existing principals.

## Repository Sources

`repo` is the stable identity used in cache paths, mount paths, and
`AGENT_REPO`. When `cloneUrl` is empty, Centaur derives
`https://github.com/<repo>.git`; an explicit `cloneUrl` may use `http://` or
`https://` and may point to GitLab or another Git server. URLs containing a
username, password, query string, or fragment are rejected.

| Helm value or env var | Set from | Controls |
| --- | --- | --- |
| `overlays.sources[*].cloneUrl` | Helm value. | Git remote for an ordered tools, workflows, or skills source. |
| `toolServer.cloneUrl` | Helm compatibility value. | Git remote for the primary tool source when `overlays.sources` is empty. |
| `toolServer.extraSources[*].cloneUrl` | Helm compatibility value. | Git remote for an additional tool source. |
| `repoCache.repositories[*].cloneUrl` | Helm value on object entries. | Git remote for a cache-only repository. |
| `repoCache.gitCredentials.username` | Helm value; default `oauth2`. | Username returned by `GIT_ASKPASS`. GitLab deploy tokens require their generated username. |
| `repoCache.gitCredentials.existingSecretName`, `secretKey` | Kubernetes Secret reference. | Token/password mounted into repo-cache; generic credentials take precedence over `repoCache.githubToken`. |
| `toolServer.gitCredentials.*` | Kubernetes Secret reference. | Direct-clone credential used only when repo-cache is disabled and mounted only into bootstrap cloning surfaces, not the long-running agent; generic credentials take precedence over `toolServer.githubToken`. |
| `repoCache.egressPorts` | Helm value; default `[443]`. | Destination TCP ports allowed for repo-cache. Add a custom HTTP port such as `82` when required. |
| `REPOSITORY_CLONE_URLS` | Chart-rendered JSON for repo-cache. | Mapping from stable repository identity to resolved explicit remotes. Readiness stores SHA-256 URL hashes, not raw URLs. |
| `KUBERNETES_TOOLS_CLONE_URL`, `KUBERNETES_TOOLS_EXTRA_SOURCES` | Chart-rendered for api-rs. | Primary and additional remotes propagated to sandbox init containers. |

:::warning[Plain HTTP has no transport confidentiality]
An `http://` clone sends the Git username, token, and repository contents in
plaintext. Restrict it to trusted isolated networks and use HTTPS when
available. Never embed credentials in `cloneUrl`.
:::

With `repoCache.enabled: false`, direct tool clones pass through each sandbox's
iron-proxy. A literal IP such as `192.168.50.10` receives only an exact `/32`
(IPv4) or `/128` (IPv6) rule for the clone port, scoped to that sandbox's
repository access. The api-rs startup checkout receives the same exact target
rule. Sandbox resume and proxy repair reuse the CIDR/port targets recorded at
creation, even if the release configuration later changes. DNS names do not
add broad public custom-port rules. Use repo-cache for private DNS remotes or
DNS remotes on ports other than the proxy's baseline HTTPS port. Authenticated
direct clones run only during sandbox bootstrap; background refresh is disabled
because the long-running agent does not receive the Git Secret.

## Development repositories and publication

This is separate from overlay and tool source cloning. It lists all projects
visible to one deployment GitLab Token, lets each task select zero or more of
them, and stores the working trees on a task-scoped PVC.

| Helm value or env var | Set from | Controls |
| --- | --- | --- |
| `workspaceRepositories.enabled` / `DEVELOPMENT_WORKSPACE_ENABLED` | Helm value, default `false`. | Enables the GitLab catalog and durable Workspace preparation. Requires the `agent-k8s` sandbox backend. |
| `workspaceRepositories.gitlab.baseUrl` / `GITLAB_BASE_URL` | Helm value. | Exact GitLab HTTP(S) origin; paths, credentials, query strings, fragments, and redirects are rejected. |
| `workspaceRepositories.gitlab.allowInsecureHttp` / `GITLAB_ALLOW_INSECURE_HTTP` | Helm value, default `false`. | Explicitly accepts plaintext HTTP. Both Helm and api-rs fail closed without it. |
| `workspaceRepositories.gitlab.egressCidrs` | Helm value. | Stable GitLab ingress CIDRs used by NetworkPolicy. Required when NetworkPolicy is enabled because Kubernetes policy cannot target a DNS name. |
| `workspaceRepositories.gitlab.secretRef`, `secretKey` | Explicit Kubernetes Secret reference. | Shared GitLab bot Token used only by api-rs catalog calls and short-lived Provisioner/Publisher jobs. |
| `workspaceRepositories.gitlab.pageSize`, `requestTimeoutSecs` | Helm values. | Catalog pagination and GitLab request timeout. |
| `workspaceRepositories.storage.className`, `size` | Helm values. | Workspace PVC storage class and requested capacity. |
| `workspaceRepositories.storage.accessMode` / `DEVELOPMENT_WORKSPACE_STORAGE_ACCESS_MODE` | Helm value, default `ReadWriteOnce`. | Use `ReadWriteMany` when sandbox, Collector, and Publisher can schedule on different nodes; use `ReadWriteOnce` only when one-node attachment is guaranteed. |
| `workspaceRepositories.provisionerImage.*` | Helm values; defaults to the sandbox image. | Image and pull policy for Provisioner, Collector, and Publisher jobs. |
| `gitlabPublishing.enabled` / `GITLAB_PUBLISHING_ENABLED` | Helm value, default `false`. | Enables approval-triggered branch pushes and merge-request creation. |
| `gitlabPublishing.secretRef`, `secretKey` | Explicit Kubernetes Secret reference. | Must reference the same Token as repository discovery in the first release. |
| `gitlabPublishing.branchPrefix` | Helm value; currently `centaur`. | Prefix for deterministic publication branches. |

The GitLab credential must be a Personal, Project, or Group Access Token that
GitLab accepts in the `PRIVATE-TOKEN` header for `GET /api/v4/projects`, and it
must be able to clone every intended project. A deploy token or credential that
works only with Git clone cannot drive the repository catalog. When publication
is enabled the Access Token also needs the minimum project API/repository rights
to push branches and create merge requests. The Token is mounted as a file into
api-rs for catalog requests and by Secret reference into short-lived jobs. It is
not injected into Feishubot, Console, the browser, `harness-server`, agent
sandboxes, or persistent Workspace files. Provisioner and Publisher use distinct
ServiceAccounts and api-rs rejects a publishing configuration that collapses
them to one identity.

:::danger[Plain HTTP exposes the shared read/write Token]
Set `allowInsecureHttp: true` only for an isolated network whose GitLab has no
HTTPS endpoint. The flag is an explicit risk acceptance, not encryption. Use
`https://` whenever possible and restrict `egressCidrs` to the GitLab ingress.
:::

## China Feishu bot

Use a China Feishu enterprise self-built application with bot capability, not
a fixed-group custom webhook robot. The bot uses a long connection and does not
need a public event callback URL.

| Helm value or env var | Set from | Controls |
| --- | --- | --- |
| `feishubot.enabled` | Helm value, default `false`. | Deploys the single-replica China Feishu ingress. |
| `feishubot.secretRef` | Explicit Kubernetes Secret reference. | Secret containing the app ID, app secret, bot open ID, and internal api-rs key. |
| `feishubot.appIdKey`, `appSecretKey`, `botOpenIdKey`, `apiKeyKey` | Helm values. | Key names inside `secretRef`; defaults are `app-id`, `app-secret`, `bot-open-id`, and `api-key`. |
| `feishubot.allowedTenantKeys` / `FEISHU_TENANT_ALLOWLIST` | Helm value. | Required non-empty tenant allowlist. Events from other tenants are ignored. |
| `feishubot.port` | Helm value, default `3005`. | Health, readiness, and Prometheus endpoint port. |
| `CENTAUR_CONSOLE_PUBLIC_URL` | Rendered from `console.publicUrl`. | Adds authenticated Console ChangeSet links to result cards. |

`/health` reports process liveness, `/ready` requires an established Feishu long
connection, and `/metrics` exposes bounded event, deduplication, acknowledgement,
render, recovery, and optimistic-conflict signals. Metric labels never include
tenant keys, user IDs, message IDs, task text, or source code.

Sandbox lifecycle:

| Env var or value | Set from | Controls |
| --- | --- | --- |
| `SESSION_IDLE_TIMEOUT_MS` | `slackbotv2.extraEnv`; default is up to 3 hours. | Slackbot v2 execute idle timeout. If `SESSION_MAX_DURATION_MS` is lower than 3 hours and this value is unset, Slackbot v2 caps the default idle timeout to the max duration. |
| `SESSION_MAX_DURATION_MS` | `slackbotv2.extraEnv`. | Optional per-execution max duration forwarded to api-rs. api-rs rejects requests where `idle_timeout_ms` is greater than `max_duration_ms`. |

| `apiRs.sandboxReapIntervalSecs` / `SESSION_SANDBOX_REAP_INTERVAL_SECS` | Helm value, default `300`. | How often api-rs sweeps observed sandboxes for max-lifetime expiry. |

There is no separate suspended-only delete timer. Pausing is controlled by the
per-execution idle timeout; deletion is controlled by sandbox max lifetime.
