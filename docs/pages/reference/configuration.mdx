# Configuration

Most Centaur settings come from Helm values and are rendered into service
environment variables by service-specific templates under `contrib/chart/templates/`.

Use these as the main extension points:

| Source | Use |
| --- | --- |
| `secretManager.existingSecretName` | Required runtime secrets such as database, Slack, sandbox signing, and 1Password credentials. |
| `apiRs.extraEnv` | Rust API feature flags, telemetry exporter settings, and deployment-specific overrides. |
| `apiRs.metrics.*` | Prometheus/VictoriaMetrics scrape metadata for the Rust API `/metrics` endpoint. |
| `apiRs.nodeSelector`, `apiRs.affinity`, `apiRs.tolerations` | Controls scheduling for api-rs pods, including dedicated tainted node pools. |
| `console.publicUrl` | Required. The Console origin users and MCP clients reach. api-rs serves the Console, so this also selects the Console host. |
| `tokenBroker.*` | token-broker, which refreshes Console broker credentials: replicas, poll interval, concurrency, scheduling, and metrics. |
| `postgres.nodeSelector`, `postgres.affinity`, `postgres.tolerations` | Controls scheduling for the bundled PostgreSQL pod. Ensure selected nodes can mount its persistent storage. |
| `postgres.enabled`, `externalDatabase.*` | Replaces the bundled PostgreSQL with an external server such as RDS or Cloud SQL, scopes NetworkPolicy egress to it, and selects the company-context text-search backend. See [Use an External PostgreSQL](/deploying-in-production#use-an-external-postgresql). |
| `companyContext.*` | Company-context ingestion service, default off. Formerly `experimentalCompanyContext.*`, still accepted as an alias. Requires `OPENAI_API_KEY`, `SLACK_BOT_TOKEN`, and `CENTAUR_JWT_SIGNING_SECRET`. See [Company Context](/operate/company-context). |
| `slackbotv2.extraEnv` | Slackbot HTTP, Slack, and cross-org behavior. |
| `sandbox.extraEnv` | Extra variables copied into every sandbox pod through `KUBERNETES_SANDBOX_EXTRA_ENV`. |
| `overlays.sources` | Ordered repo-cache-backed overlay repos for tools, workflows, skills, and Code Mode connectors; subdirs default to `tools`, `workflows`, `.agents/skills`, and `connectors`. |
| `overlay.systemPrompt` | Small inline prompt overlay escape hatch. |

Tool credentials are not listed here. Tool plugins declare their own secrets in
`tools/**/pyproject.toml`; Centaur resolves them through `secret(...)` and
iron-proxy instead of treating them as global platform configuration.

## Console and Permission Control Plane

The Console stores principals, roles, grants, sandbox capabilities, and
encrypted secret-source configuration. The chart renders its internal URL and
admin API key into api-rs. See [Advanced Permissioning](/secrets/advanced-permissioning)
for the operator workflow.

| Env var or value | Set from | Controls |
| --- | --- | --- |
| `IRON_CONTROL_DATABASE_URL` | `secretManager.existingSecretName`. | Console database connection. Required by api-rs, which reads principals and their effective config through it in read-only sessions. Keep it separate from the api-rs logical database. |
| `IRON_CONTROL_INITIAL_USER_EMAIL`, `IRON_CONTROL_INITIAL_USER_PASSWORD` | `secretManager.existingSecretName`; local bootstrap generates defaults when absent. | Creates the initial Console admin when no user exists. |
| `IRON_CONTROL_AR_ENCRYPTION_PRIMARY_KEY`, `IRON_CONTROL_AR_ENCRYPTION_KEY_DERIVATION_SALT` | `secretManager.existingSecretName`; local bootstrap generates them when absent. | Encrypts credential material at rest. Keep these stable after first boot. |
| `IRON_CONTROL_SECRET_KEY_BASE` | `secretManager.existingSecretName`; local bootstrap generates it when absent. | The input api-rs derives its Console session keys from (via `CONSOLE_SESSION_SECRET`). |
| `CENTAUR_JWT_SIGNING_SECRET` | `secretManager.existingSecretName`; local bootstrap generates it when absent. | Signs Console-issued MCP tokens, API client access tokens, and the single `centaur-sandbox` token proxy-sync mints for each sandbox. |
| `console.publicUrl` | Helm value, required. | Public Console origin: used for links and MCP authorization metadata, and as the api-rs session-cookie and unsafe-request Origin check and the host that selects the Console router. |
| `CONSOLE_SESSION_SECRET` | The chart sets it from `<secretManager.envPrefix>IRON_CONTROL_SECRET_KEY_BASE`; nothing to add to the Secret. | The input api-rs derives its Console session-cookie and SSO keys from (PBKDF2 with its own labels). Rotating it signs every browser and in-flight flow out. |
| `console.passwordLoginEnabled` | Helm value, default `true`. | Enables the break-glass email and password login. Disable after SSO is configured for a public Console. |
| `console.ssoEmailDomains` | Helm value. | Limits Google, Slack, or Okta SSO admission by email domain. Empty accepts any IdP-authenticated email. |
| `console.oktaOauth.enabled` | Helm value, default `false`. | Enables Okta OIDC login for the Console. |
| `console.oktaOauth.issuer` | Helm value. | Okta organization or custom authorization-server issuer used for OIDC discovery. |
| `console.oktaOauth.tokenEndpointAuthMethod` | Helm value, default `client_secret_basic`. | Client authentication method configured on the Okta application: `client_secret_basic` or `client_secret_post`. |
| `CENTAUR_CONSOLE_OKTA_CLIENT_ID`, `CENTAUR_CONSOLE_OKTA_CLIENT_SECRET` | `secretManager.existingSecretName` when Okta login is enabled. | Okta OIDC web application credentials. |
| `apiClients.enabled`, `CENTAUR_API_CLIENTS_ENABLED`, `CENTAUR_CONSOLE_API_CLIENTS_ENABLED` | Helm value, default `false`. | Enables [API clients](/operate/api-clients): the Console's **API Clients** page and api-rs `/oauth/token`. Off, api-rs also rejects API client tokens. |
| `apiRs.syncInfraSecrets`, `IRON_CONTROL_SYNC_INFRA_SECRETS` | Helm value, default `true`. | Upserts the shared `infra` role and its harness/platform secrets. Set false only when another process owns that shared Console state. |
| `IRON_CONTROL_URL`, `IRON_CONTROL_API_KEY` | Operator shell for `centaur-perms`; the chart renders `IRON_CONTROL_URL` for api-rs. | For `centaur-perms`, the Console API and an operator key. api-rs uses only the URL, as the Console address it hands sandboxes: it writes the Console database directly, as the Console system user (`system@centaur.invalid`). |

Default roles and default sandbox capabilities are stored in the Console, not
as Helm values. Configure them in **System Settings** before new principals are
created. Changing a default does not rewrite existing principals.

## API-RS

| Env var or value | Set from | Controls |
| --- | --- | --- |
| `TOOL_DIRS`, `PLUGINS_DIR` | Chart-rendered from `overlays.sources[*].toolsSubdir` (default `tools`); fallback to `PLUGINS_DIR`. | Tool discovery paths. |
| `RUST_LOG` | Chart sets `info`; override with `apiRs.extraEnv`. | Rust tracing filter for the API-RS binary and crates. |
| `OTEL_SERVICE_NAME` | `apiRs.extraEnv`; defaults to `centaur-api-rs`. | OpenTelemetry service name used by trace backends. |
| `CENTAUR_ENVIRONMENT`, `DEPLOY_ENV`, `ENVIRONMENT` | `apiRs.extraEnv` or deployment env. | Deployment environment resource attribute for telemetry. |
| `OTEL_TRACES_EXPORTER` | `apiRs.extraEnv`. | Set to `otlp` to force OTLP trace export, or `none`/`off` to disable it. |
| `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | `apiRs.extraEnv`. | Enables OTLP trace export to Tempo, Jaeger, or another OTLP collector. |
| `WORKFLOW_DISCOVERY_URL` | Chart-rendered from the `workflow-discovery` Service (port 8090). | Workflow discovery service api-rs calls for workflow metadata. Required. |
| `workflowDiscovery.resources` | Helm value. | The `workflow-discovery` Deployment (`workflow-host serve` from `sandbox.image`). It is placed and isolated like sandbox pods: it follows `sandbox.nodeSelector`, `tolerations`, `runtimeClassName`, `priorityClassName`, `hostUsers`, `podAnnotations`, and `containerSecurityContext`, but not `sandbox.serviceAccountName`. It reads those Helm values, not `SESSION_SANDBOX_*` overrides set through `apiRs.extraEnv`. It always keeps a read-only root filesystem. It mounts workflow sources read-only, receives `WORKFLOW_DIRS` and the `SESSION_SANDBOX_PASSTHROUGH_ENV` values from api-rs with each request (what run sandboxes get), holds no secrets, and under `networkPolicy.enabled` accepts only api-rs and makes no outbound connections. |
| `apiRs.mcpEnabled` / `CENTAUR_MCP_ENABLED` | Helm value, default `true`; unset also means enabled; override with `apiRs.extraEnv`. | `true` serves `/mcp` through Code Mode: api-rs runs a `centaur-codemode` sandbox per principal and forwards `centaur_catalog_search`, `centaur_catalog_load` and `centaur_execute` over HTTP. A principal normally has one sandbox; with several api-rs replicas or during a rolling deploy it may briefly have more, which is harmless. api-rs caches each endpoint for 30 seconds, adopts a running sandbox when its cache is cold, and otherwise creates one; readiness is the sandbox pod's readiness probe on `/healthz`, so api-rs never polls the sandbox. Replacing the engine image or changing a principal's sandbox capabilities builds a new sandbox (a new `centaur.ai/codemode-fingerprint` generation) and stops the old one after 12 minutes, longer than the longest cell. `false` (or `0`, `no`, `off`) does not serve `/mcp` or its OAuth protected-resource metadata, and api-rs starts no Code Mode sandboxes. This replaces `apiRs.mcpV2Enabled` / `CENTAUR_MCP_V2_ENABLED`, which is now ignored. Connector credentials come from the deployment's tool secret declarations, so a connector works only if a tool declares the secrets it needs. |
| `codemode.image` / `CENTAUR_CODEMODE_IMAGE` | Helm value (`repository:tag`), default `centaur-codemode:latest`; override with `apiRs.extraEnv`. api-rs also defaults to `centaur-codemode:latest` when the variable is unset or blank. | Dedicated slim Code Mode runtime image, used when `apiRs.mcpEnabled` is `true`. It contains the `centaur-codemode` binary and the repository connectors at `/opt/centaur/connectors`. Pull policy and pull secrets reuse `sandbox.image.pullPolicy` and `global.imagePullSecrets`. |
| `codemode.executor.*` | Helm values, `enabled` default `false`; requires `brain.enabled` and `codemode.executor.existingSecretName`. | Runs the Code Mode executor (`centaur-codemode serve-executor`) from `codemode.image` and a shared tenancy iron-proxy from `ironProxy.image`, giving nanocode turns the Code Mode tools. The turn token api-rs mints is the only credential on the path: the brain sends it with every exec, search, and load, and the executor sends every connector request through the tenancy iron-proxy with it as `Proxy-Authorization`. The proxy verifies it, fetches the turn principal's configuration from proxy-sync, and injects that principal's credentials. The Secret has three keys: `token-signing-key` (api-rs only), `token-public-key` (brain, executor, tenancy iron-proxy, proxy-sync), and `sync-token` (tenancy iron-proxy and proxy-sync); `just bootstrap-codemode-secret` creates it. The executor loads the image's connectors and every overlay's. See `crates/centaur-codemode/README.md`. |
| `apiRs.metrics.scrapeAnnotations` | Helm value, default `true`. | Adds Prometheus scrape annotations to the API-RS Pod template. The Service is not annotated, so collectors that scrape both pods and service endpoints scrape each pod once. |
| `apiRs.metrics.path` | Helm value, default `/metrics`. | Metrics scrape path for annotation-based discovery. |
| `apiRs.metrics.annotations` | Helm value. | Additional scrape annotations for Prometheus-compatible collectors. |
| `apiRs.activitySummary.*` | Helm values, default disabled. | Enables API-RS to summarize live session activity into durable `session.activity_summary` events. |
| `SLACK_BOT_TOKEN` | Explicit `secretKeyRef` from `secretManager.existingSecretName`. | Slack Web API access for api-rs Slack proxy and workflow Slack helpers. |
| `OPENAI_API_KEY` | Secret mounted into api-rs, or `apiRs.extraEnv` for local/dev overrides. | OpenAI credential for activity summaries; the feature stays disabled when no key is present. |
| `OPENAI_BASE_URL` | `apiRs.extraEnv`; default `https://api.openai.com/v1`. | OpenAI-compatible Responses API base URL for every api-rs OpenAI caller: Codex, generated session titles, and activity summaries. API-RS passes it into Codex sandboxes and derives iron-proxy's `OPENAI_API_KEY` host scope from it; `api.openai.com` and `us.api.openai.com` are always included. |
| `SESSION_ACTIVITY_SUMMARY_OPENAI_BASE_URL` | Deprecated `apiRs.activitySummary.openaiBaseUrl` compatibility setting. | Existing activity-summary endpoint override. `OPENAI_BASE_URL` takes precedence when both are set. |
| `SESSION_ACTIVITY_SUMMARY_MODEL` | `apiRs.activitySummary.model`, default `gpt-5.4-nano`. | Model used for the short live activity sentence. |
| `apiRs.activitySummary.progressUpdates.enabled` / `SESSION_PROGRESS_UPDATE_ENABLED` | Helm value, default `false`. Requires `apiRs.activitySummary.enabled`. | Feature flag for progress messages. When on, api-rs writes a short progress message from recent activity as a durable `session.progress_update` event for long-running executions, which Slackbot v2 posts as a separate thread message. |
| `apiRs.activitySummary.progressUpdates.afterSecs` / `SESSION_PROGRESS_UPDATE_AFTER_SECS` | Helm value, default `60`. | Execution age before the first progress message. |
| `apiRs.activitySummary.progressUpdates.intervalSecs` / `SESSION_PROGRESS_UPDATE_INTERVAL_SECS` | Helm value, default `120`. | Minimum time between progress messages for one execution. A message is written only when new activity arrived since the previous one. |

Sandbox lifecycle:

| Env var or value | Set from | Controls |
| --- | --- | --- |
| `SESSION_IDLE_TIMEOUT_MS` | `slackbotv2.extraEnv`; default is up to 3 hours. | Slackbot v2 execute idle timeout. After an execution reaches a terminal state, api-rs pauses the sandbox if no newer execution has used that sandbox. If `SESSION_MAX_DURATION_MS` is lower than 3 hours and this value is unset, Slackbot v2 caps the default idle timeout to the max duration. |
| `SESSION_MAX_DURATION_MS` | `slackbotv2.extraEnv`. | Optional per-execution max duration forwarded to api-rs. api-rs rejects requests where `idle_timeout_ms` is greater than `max_duration_ms`. |
| `apiRs.sandboxMaxLifetimeSecs` / `SESSION_SANDBOX_MAX_LIFETIME_SECS` | Helm value, default `259200` (72 hours). | Restart-surviving sandbox deletion backstop. The reaper stops any non-terminal sandbox older than this, whether it is running or suspended. A warm-pool sandbox's age counts from when a session claims it, and a sandbox whose session has a queued or running execution is skipped until that turn ends, unless the turn itself has run longer than this. Set `0` to disable max-lifetime reaping. |
| `apiRs.sessionEventsRetentionDays` / `SESSION_EVENTS_RETENTION_DAYS` | Helm value, default `0` (disabled); range `0` through `3650`. | Deletes only `session.output.line` events older than this many days, once their execution also completed before the cutoff. Other session event types are preserved. Events without an execution expire by event age alone. Requires the [manual retention index](#stdout-event-retention). Sweeps skip deletion when the index is missing or invalid. |
| `apiRs.sessionEventsRetentionSweepIntervalSecs` / `SESSION_EVENTS_RETENTION_SWEEP_INTERVAL_SECS` | Helm value, default `300`. | How often api-rs runs a session-event retention sweep when retention is enabled. |
| `apiRs.sandboxReapIntervalSecs` / `SESSION_SANDBOX_REAP_INTERVAL_SECS` | Helm value, default `300`. | How often api-rs sweeps observed sandboxes for max-lifetime expiry and orphaned proxy resources. |
| `apiRs.sandboxOrphanSweepGraceSecs` / `SESSION_SANDBOX_ORPHAN_SWEEP_GRACE_SECS` | Helm value, default `600`. | Minimum age of an iron-proxy resource with no live Sandbox before the orphan sweep may delete it. |
| `apiRs.activitySummary.reasoningEffort` / `SESSION_ACTIVITY_SUMMARY_REASONING_EFFORT` | Helm value, default `low`. | Reasoning effort sent with the activity-summary call. The output budget is small, so a server that resolves an absent effort to its highest level spends the whole budget reasoning and returns an `incomplete` response with no message. Set empty to omit the parameter for a server that rejects it. |
| `SESSION_TITLE_REASONING_EFFORT` | Env on api-rs, default `low`. | The same, for the session-title call, whose budget is 24 output tokens. Set empty to omit the parameter. |

There is no separate suspended-only delete timer. Pausing is controlled by the
per-execution idle timeout; deletion is controlled by sandbox max lifetime.

| `SLACKBOTV2_AUTO_JOIN_CREATED_CHANNELS` | `slackbotv2.autoJoinCreatedChannels`. | Joins newly-created public channels after subscribed `channel_created` events. Requires `channels:read` and `channels:join`. Defaults to `false`. |

| `SLACKBOTV2_ACK_REACTION` | `slackbotv2.ackReaction`. | Slack emoji name used for turn acknowledgements. Defaults to `eyes`. |

| `SLACKBOTV2_STEERING_REACTION` | `slackbotv2.steeringReaction`. | Slack emoji name used for steering acknowledgements. Defaults to `hourglass_flowing_sand`. |
| `SLACKBOTV2_GENERATIVE_UI_ENABLED` | `slackbotv2.generativeUi.enabled`. | Renders a generative UI card from one fenced ```json-render block in a final answer, using json-render on the Chat SDK card model (header, text, fields, native table, native chart, divider, image, link buttons). The block leaves the streamed markdown and the card is posted as a second message in the thread; a spec that fails validation or Slack's limits stays in the answer as a code block, with a warning log and the `slackbotv2_generative_ui_cards_total` metric. Requests for plain text only get no card and no note. slackbotv2 tells the agent about the card on the first Slack turn it executes in a thread (and again after a harness restart), so no persona change is needed and other chat surfaces never see the instruction; see `services/slackbotv2/GENERATIVE_UI.md`. Defaults to `false`, which renders answers exactly as before. |
| `SLACKBOTV2_GENERATIVE_UI_LIMITS` | `slackbotv2.generativeUi.limits`. | JSON object of per-message limits enforced before posting, with the `@json-render/chat` `CardLimits` keys (`tables`, `charts`, `fields`, `tableRows`, `tableColumns`, `chartLabel`, `chartTitle`, `chartSeries`, `chartPoints`). Defaults to `{"tables":1,"charts":2}`, the point past which the Slack adapter would degrade content instead of rendering it. |
| `SLACKBOTV2_PROACTIVITY_ENABLED` | `slackbotv2.proactivity.enabled`. | Lets the bot reply without a mention. In threads where it was mentioned, each later unmentioned reply goes to a classifier, and the bot answers when the classifier says it should; whether a reply that mentions a person is for that person is left to the classifier. Operator rules (see `SLACKBOTV2_PROACTIVITY_RULES_DIR`) remove the need for a mention at all. These messages pass the same Slack Connect and bot-author gates as mentions. An accepted message that arrives while Centaur is working steers the running turn, like a mentioned follow-up. A stop command silences proactive replies in its thread until the next mention. Defaults to `false`. |
| `SLACKBOTV2_PROACTIVITY_CLASSIFIER` | `slackbotv2.proactivity.classifier`. | Model backend for proactive decisions. Only `openai` is available right now. It asks the OpenAI Decisions API a respond predicate, or one predicate per rule, with `SLACKBOTV2_PROACTIVITY_MODEL` (default `gpt-6-luna`) and `SLACKBOTV2_PROACTIVITY_OPENAI_BASE_URL`, and reads `SLACKBOTV2_PROACTIVITY_OPENAI_API_KEY` or `OPENAI_API_KEY`. Startup fails when proactivity is enabled and the key is missing. |
| `SLACKBOTV2_PROACTIVITY_RULES_DIR` | Mounted from a ConfigMap rendered from `slackbotv2.proactivity.defaultRules` and `slackbotv2.proactivity.channelRules`. | Directory of rule files that remove the need for a mention. Each file is a JSON array of at most 20 rules, each with a unique `name`, `when` criteria, and optional `context`. `default.json` applies in every channel; `<CHANNEL_ID>.json` replaces it in that Slack conversation, and an empty list turns rule matching off there. The bot replies to any unmentioned message that the classifier judges to meet a rule, starting a thread under a top-level message; that thread then counts as mentioned. Rules are checked in order and the first match wins. When that match starts a turn, the agent is told which rule matched along with its `context`, once per rule per thread, since later turns have it in the session. A harness restart resends the matched rule's context and forgets the rest. Read at startup. If the directory cannot be read or a file is invalid, the bot logs a warning and starts with no rule matching; mentioned-thread replies still work. Unset means no rule matching. |
| `SLACKBOTV2_PROACTIVITY_DEBOUNCE_MS` | `slackbotv2.proactivity.debounceMs` (rendered only when above 0). | Quiet period, in milliseconds, before an unmentioned message in an idle thread is classified. Each message restarts the wait and only the newest one, by Slack timestamp, is classified, with the other messages that arrived during the wait judged together with it as one message (minus any a turn that started meanwhile already has), so a message sent in parts gets one decision and one turn that sees every part. Messages that arrive while Centaur is working are classified at once and steer the turn when accepted. Every proactive reply waits this long. Unset classifies each message at once. |
| `SLACKBOTV2_PROACTIVITY_TIMEOUT_MS` | `slackbotv2.proactivity.timeoutMs`. | Classifier deadline; defaults to 2s. A late or failed decision counts as no reply. |
| `SLACKBOTV2_DEFAULT_HARNESS` | `sandbox.harnessEngine`. | Base harness for new Slack threads without an explicit flag or channel default. |
| `SLACKBOTV2_ENABLED_HARNESSES` | Unrestricted when unset. | Comma-separated harness wire values allowed by Slack routing, set through `slackbotv2.extraEnv`. Disabled message overrides, channel defaults, and sticky threads fall back to the enabled deployment default. |
| `SLACKBOTV2_CHANNEL_DEFAULTS` | `slackbotv2.channelDefaults`. | Per-channel default persona / harness / model / provider / reasoning as a JSON object keyed by Slack conversation id, where each value is an object of optional `persona`/`harness`/`model`/`provider`/`reasoning` fields (same vocabulary as the inline flags, so `harness: claude`, `provider: bedrock`, and Claude model aliases like `opus` all work), e.g. `{"C0ENG":{"harness":"claude","model":"opus","reasoning":"high"},"C0TRIAGE":{"reasoning":"low"}}`. A model is only meaningful within a harness, so name the harness alongside it. Applied when a message in that channel carries no explicit/sticky per-thread flag (below such a flag, above the deployment/baked default) and forwarded onto the harness input line so it takes effect; setting the harness restarts a thread onto it like a `--claude`/`--codex` flag. `reasoning` affects the Codex, Claude Code, and Pi harnesses. `persona` names a deployed persona and, like `--persona`, applies only when the thread's session is created. Malformed JSON and unrecognized field values are logged and ignored. |

Sandbox context file: before a sandbox's first turn, `harness-server` writes
`~/.centaur/sandbox.json` with the session's `thread_key`, the harness, the
persona, and under `sandbox` the Console principal, capabilities, and redacted

`sandbox` is `null` and `sandbox_error` says why. Tools read it through
`centaur_sdk.sandbox_context()` and `centaur_sdk.sandbox_thread_key()`. The file

`~/.centaur/turn-trace.json` with the turn's `traceparent`, `thread_key`, and
`execution_id`, and removes it when the turn ends. `centaur-codemode exec`
parents its cell, tool-call, and request spans on it.

### Stdout Event Retention

Retention is disabled by default. Its index is installed separately from API-RS
startup migrations, so an index build failure does not prevent the API from
starting. Create the index before enabling retention.

Connect `psql` to the application database with an account that owns
`session_events`. Use your normal libpq connection settings and credential file.
From the repository root, run:

```sh
psql -X --set ON_ERROR_STOP=1 \
  --file crates/centaur-session-sqlx/manual-migrations/session_events_retention_index.sql
```

The script creates a partial index concurrently. Run it outside a transaction;
do not use `psql --single-transaction`. Ordinary reads and writes can continue,
but the build adds database load and can wait for existing transactions.

Verify the index after the command succeeds:

```sql
SELECT indexrelid::regclass AS index_name, indisvalid, indisready, indislive
FROM pg_catalog.pg_index
WHERE indexrelid = to_regclass('session_events_stdout_created_at_idx')
  AND indrelid = 'session_events'::regclass;
```

Expect one row with all three flags set to `true`. Then set
`apiRs.sessionEventsRetentionDays` or `SESSION_EVENTS_RETENTION_DAYS` to a value
from `1` through `3650`. An execution's stdout becomes eligible after its
completion time passes the retention cutoff. Deletions remain batched, so a
large backlog can take several sweeps to drain.

If a build fails, inspect the index before retrying. No row means the index is
absent and the creation script can be retried after addressing the failure.
If the index exists but is invalid, repair it outside a transaction:

```sql
REINDEX INDEX CONCURRENTLY session_events_stdout_created_at_idx;
```

Verify the flags again after repair. The creation script deliberately fails if
the name already exists, so a retry cannot silently accept an invalid index.
An already valid index does not need to be recreated.

Each retention sweep checks the index. If it is missing or invalid, the worker
logs `session_events_retention_skipped` and deletes nothing. API-RS stays
available. After the index is repaired, the next sweep can proceed without
another restart. Setting retention back to `0` disables the worker.
